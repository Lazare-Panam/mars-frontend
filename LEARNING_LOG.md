- [ ] 2026-09-15 — Why did category & variant pages render content in static HTML but product-detail pages showed a spinner, when the fix was the same? — turned out most were a *backend data gap* (`/api/product/{id}/detail` returns 404 for the one-piece series), not a frontend bug. ## Concepts To Learn Next
- [ ] 2026-10-05 — **Hiding non-differentiating columns in a spec table** — in the Series 10 variants table, Port/Pressure/Body/Seats/Design are identical on every row; only Size & Locking Device vary. A column whose value is constant across all rows carries no information and just adds clutter. The pattern (common in faceted product/spec grids) is to compute `new Set(rows.map(r => r[col]))` per column and drop any with `size === 1`. Worth thinking about: where to compute it (full set vs. current filtered set) and the edge case of a single-row result.
- [ ] 2026-10-05 — **Styling MUI Accordion via its state classes & internal slots** — making `VariantsSidebar` look like the marsselect "Shop By" cards meant restyling MUI's Accordion internals rather than wrapping it: `"&:before": { display: "none" }` to kill the default top divider, `"&.Mui-expanded": {...}` to swap grey→white + add a border only when open, and `"& .MuiAccordionSummary-content"` to retune the header spacing. Worth reading: MUI docs → Accordion → "Customization", and the general concept of targeting a component's internal slots and state classes (`.Mui-expanded`, `.Mui-checked`) through the `sx` prop.
- [ ] 2026-09-18 — **MUI `variant` vs `component`, and one-`<h1>`-per-page semantics** — the missing-H1 fix hinged on this: `variant` controls the *look*, `component` controls the actual DOM tag. `<Typography variant="h2">` renders an `<h2>` by default; `component="h1"` makes it an `<h1>` with h2 styling. Worth reading: MUI Typography docs "Changing the semantic element", and MDN's page on document outline / why each page should have exactly one `<h1>`.
- [ ] 2026-09-18 — **React Server Components boundary: you cannot pass a function/component as a prop from a Server Component to a Client Component** — this is what broke the first `/product-index` attempt: `<Chip component={Link}>` inside a server component threw "Functions cannot be passed directly to Client Components". `tsc` passed; only running the page caught it (hence: always render the page, not just type-check). Fix was plain `next/link` anchors + a CSS module. Read the official guide: search "Next.js Server and Client Components — passing props" and note the rule that props crossing the boundary must be serializable.
- [ ] 2026-09-18 — **`rel="canonical"` for duplicate URLs** — the duplicate-title report was mostly the *same* variant served at two URLs (`/products/ball-valves/…` vs `/products/<real-subcategory>/…`), because the `[id]` route segment is never validated against the product. "Unique titles" is the wrong fix for that; a canonical tag (or removing the umbrella links) is the right one. Google's own doc: search "Google Search Central consolidate duplicate URLs" — focus on when to use rel=canonical vs a redirect, and that a canonical is a *hint*, not a directive.
- [ ] 2026-09-15 — **TanStack Query SSR: `prefetchQuery` + `dehydrate` + `<HydrationBoundary>`** — this is exactly the pattern used to make the client-rendered product/category/variant pages emit real HTML for crawlers, without rewriting the MUI components. Read the official guide: https://tanstack.com/query/latest/docs/framework/react/guides/advanced-ssr — focus on why `staleTime > 0` matters (so the client doesn't refetch and discard the server-rendered data) and how `dehydrate` only serializes *successful* queries by default (which is why 404'd products fall back to the client fetch).
